# Предложение по навигации — Lost Kingdom

> Самодостаточный документ для внешнего ревью (можно дать почитать другой модели).
> Содержит контекст + одну итоговую идею (рекомендованную).

## Что за игра

2D fantasy map-игра на **Godot 4.6 (GDScript)**. Герой перемещается по глобальной карте
королевства между фиксированными точками по дорогам (не свободное движение).
Игровой цикл: выбрал соседнюю локацию → герой идёт по дороге → событие (бой/квест/поиск)
→ награда → открываются новые соседние локации. Карта раскрывается через туман войны.

## Проблема (почему месяц не могли стабильно дойти)

Сейчас в проекте **две системы перемещения одновременно**:

1. **Старая** — Path2D-кривые, нарисованные так, что заканчиваются прямо в иконках локаций.
   Направление движения она пыталась угадывать по геометрии клика (tangent / projection / dot).
   На развилках это ломалось: клик «в сторону следующей дороги» проецируется назад на текущую
   кривую → герой ехал не туда / застревал / шёл задом.
2. **Новая (V2)** — граф узлов: **junction ≠ location**.
   - *Junction* — узел дороги. Проезд через него = **discover** (открыть туман / «Найдено»), НЕ вход.
   - *Location* — иконка. **Вход** — отдельное действие (`[LOCATION_ENTER]`).
   - Модель движения = **target-node** (как в Slay the Spire): клик по зоне соседнего узла →
     герой идёт по ВСЕМУ ребру Path2D туда. Один клик = одно ребро. Без угадывания направления.

**Результат последнего теста:** сама V2-навигация работает идеально — маршрут
Castle → Village → Lumbermill → Mine и обратный переход прошли чисто, ровно ожидаемыми логами,
без единого случая «угадал направление неверно».

**НО** в логи влезла старая навигация (`[ROAD_CLICK]`, `[THROUGH_ROAD]`, `[ROAD_CONTINUE]`,
пошаговый цикл `road_stop`) и `[LOCATION_ENTER]`. Причина: **вход в локацию (icon-click) до сих пор
идёт через СТАРУЮ систему**. Когда игрок кликает иконку, чтобы войти, старый мувер сдвигает героя
с узла на иконку → V2 видит «герой не на junction» → отключается → дальше всё перехватывает старая
система. То есть две системы дерутся за героя.

## Как это сделано в похожих играх

Во всех играх с таким типом карты работает **ровно одна система перемещения**, и узел — это одна
сущность, а не разнесённый по двум системам конфликт:

- **Slay the Spire / FTL** — чистый граф узлов, герой всегда стоит НА узле, клик по соседнему =
  переход.
- **Mario World (старый)** — узлы-уровни на тропинках; идёшь между узлами, на узле жмёшь «войти»
  (перемещение и вход — разные действия, но мувер один).
- **Heroes of M&M / King's Bounty** — один мувер, локация = объект-триггер, в который упираешься.

Общий принцип: **перемещение, «стоять на узле» и «войти» не должны жить в двух конфликтующих
системах.**

## Итоговое предложение (рекомендую) — модель «Mario»

Сохраняет уже принятую архитектуру `junction ≠ location` и убирает драку систем под корень.

### Суть

1. **Удалить / выключить старую навигацию полностью** — `_try_through_road`, ветки
   `[ROAD_CLICK]`, `[ROAD_CONTINUE]`, пошаговый цикл `road_stop`. Остаётся **один мувер — V2**.
   Драки систем физически не будет.

2. **Один источник позиции героя** — `_v2_current_junction` (на каком узле стоит).
   `current_location` перестаёт управлять навигацией (это закрывает и отложенную «Phase 3» —
   разделить current_junction / current_location / discovered).

3. **Два чётко разных действия:**

   ```text
   ── ПЕРЕМЕЩЕНИЕ ──────────────────────────────────────────────
   Клик по зоне соседнего узла  → V2 едет по всему ребру Path2D
                                → прибытие на узел
                                → _discover_location (туман / «Найдено»)
   (уже работает ✅)

   ── ВХОД ────────────────────────────────────────────────────
   Стоишь на узле-локации, жмёшь КНОПКУ «Войти» на UI-панели
   (НЕ клик по карте!)          → _run_location_action
                                → [LOCATION_ENTER] (бой / квест / меню)
   ```

   Главное: **клик по карте больше НИКОГДА не означает «войти».** Вход — это кнопка на панели
   локации, а не клик по иконке. Раз клик по карте не триггерит вход, старую навигацию нечем
   запустить даже случайно.

### Схема состояния

```text
Hero ──стоит на──> Junction   (единственное состояние позиции героя)
                      │
        ┌─────────────┴─────────────┐
   road-click                   кнопка «Войти»
   (соседний узел)              (активна только на текущем узле-локации)
        │                            │
   V2 edge walk                 _run_location_action
        │                            │
   _discover_location           [LOCATION_ENTER]
   (туман / «Найдено»)          (бой / квест / меню)
```

### Почему именно так

- **Чинит корень бага** — один мувер вместо двух, конфликт исчезает.
- **Сохраняет** уже принятые решения: `junction ≠ location`, discover ≠ enter, roguelite-направление
  (мимо локации можно проехать, не входя).
- **Заодно закрывает Phase 3**: `_v2_current_junction` становится единственным «где герой»,
  `current_location` уходит из навигации, вход — явное UI-действие.

### Альтернатива (на будущее, не сейчас) — модель «Slay the Spire»

Прибытие на узел-локацию = АВТО-триггер события (никакой кнопки «войти»). Максимально просто,
но мимо локации проехать нельзя — каждый узел-локация = обязательное событие. Подходит, если
захочется чистый roguelite-поход без свободного входа.
